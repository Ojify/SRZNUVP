# Сервис регистрации заявок на участие в проектах

## Назначение

Приложение представляет собой удобный интерфейс для поиска интересующих
пользователя проектов и регистрации заявок на участие в них. Консольная
версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:

- просматривать проекты в браузере;
- просматривать информацию о конкретном проекте;
- просматривать пользователей системы;
- просматривать информацию о конкретном пользователе и его заявках;
- просматривать список заявок и информацию о конкретной заявке;
- просматривать статистику по проектам и заявкам;
- проверять доступность проекта (наличие свободных мест);
- работать со справочником статусов заявок;
- хранить данные между запусками приложения.

## Используемые технологии

- Python 3;
- Django 5.2 — веб-фреймворк;
- HTML — разметка веб-страниц;
- Bootstrap 5.3 — оформление страниц;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Активные и творческие люди, готовые и желающие участвовать в различных
проектах, а также организаторы этих проектов.

## Предметная область

Предметная область охватывает процессы взаимодействия между инициаторами
проектов и потенциальными участниками. Она включает каталогизацию проектов,
управление статусами заявок и обработку данных о компетенциях пользователей.

Основными объектами предметной области являются:

- **проект** — инициатива, в которую пользователи могут подавать заявки;
- **пользователь** — физическое лицо, которое может подавать заявки
  на участие в проектах;
- **заявка** — запрос пользователя на участие в конкретном проекте;
- **статус** — справочная сущность, описывающая жизненный цикл заявки.

Пользователь может подавать заявки на участие в проектах. Один пользователь
не может одновременно иметь две активные заявки на один и тот же проект.
Заявка, отменённая пользователем, не блокирует возможность повторной подачи.

## Основные сущности

### Проект (`project`)

**Основные атрибуты:**

- `id` — уникальный идентификатор проекта;
- `name` — название проекта;
- `description` — описание проекта;
- `deadline` — срок реализации проекта;
- `max_participants` — максимальное количество участников;
- `current_participants` — текущее количество участников.

### Пользователь (`user`)

**Основные атрибуты:**

- `id` — уникальный идентификатор;
- `name` — имя пользователя;
- `email` — адрес электронной почты;
- `skills` — список навыков.

### Заявка (`application`)

**Основные атрибуты:**

- `id` — уникальный идентификатор заявки;
- `project_id` — идентификатор проекта;
- `user_id` — идентификатор пользователя;
- `created_at` — дата и время подачи заявки;
- `status` — код текущего статуса заявки.

### Статус (`status`)

**Основные атрибуты:**

- `code` — код статуса (`active`, `cancelled`, `approved`, `rejected`);
- `name` — отображаемое название;
- `description` — описание.

## Страницы веб-интерфейса

| Страница                     | URL                              | View-функция                              |
|------------------------------|----------------------------------|-------------------------------------------|
| Главная                      | `/`                              | `homepage.views.index`                    |
| Список проектов              | `/projects/`                     | `projects.views.projects`                 |
| Страница проекта             | `/projects/<int:project_id>/`    | `projects.views.project_detail`           |
| Список пользователей         | `/users/`                        | `users.views.users`                       |
| Страница пользователя        | `/users/<int:user_id>/`          | `users.views.user_detail`                 |
| Список заявок                | `/applications/`                 | `applications.views.applications`         |
| Страница заявки              | `/applications/<int:application_id>/` | `applications.views.application_detail` |
| Статистика                   | `/applications/statistics/`      | `applications.views.statistics`           |
| Админ-панель Django          | `/admin/`                        | —                                         |

Если проект, пользователь или заявка с указанным идентификатором
не найдены, соответствующая страница возвращает HTTP-код 404 и сообщение
об ошибке. Обработчик `handler404` настроен в `config/urls.py` и указывает
на `homepage.views.page_not_found`.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

- просмотр списка проектов;
- просмотр информации о проекте;
- просмотр списка пользователей;
- просмотр информации о пользователе и его заявках;
- просмотр списка заявок;
- просмотр информации о заявке;
- просмотр статистики;
- проверка доступности проекта (наличие свободных мест).

### Отложено до следующих работ

Эти операции реализованы в консольной версии (`main.py`). В веб-интерфейсе
они появятся, когда будут добавлены формы и POST-запросы:

- добавление, редактирование и удаление проекта;
- добавление, редактирование и удаление пользователя;
- подача и отмена заявки через веб-формы;
- поиск и сортировка проектов через веб-интерфейс.

## Хранение данных

Данные приложения хранятся в JSON-файлах в каталоге `data/`:

- `data/projects.json` — проекты;
- `data/users.json` — пользователи;
- `data/applications.json` — заявки;
- `data/statuses.json` — справочник статусов.

Модуль `storage.py` отвечает за чтение и запись JSON. Доменные модули
(`domain_projects.py`, `domain_users.py`, `domain_applications.py`,
`domain_statuses.py`) инкапсулируют логику работы с сущностями.

Для связи заявки с проектом и пользователем в `applications.json`
используются идентификаторы `project_id` и `user_id`.

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3). Отвечает за:

- запуск консольного приложения;
- отображение меню;
- получение данных от пользователя;
- организацию пользовательских сценариев.

### `config/`

Пакет настроек Django-проекта:

- `settings.py` — настройки проекта (локализация `ru-RU`, часовой пояс
  `Europe/Moscow`, подключённые приложения);
- `urls.py` — маршрутизация верхнего уровня, точка подключения
  приложений и `handler404`;
- `asgi.py`, `wsgi.py` — точки взаимодействия с серверами.

### `homepage`

Django-приложение, отвечающее за главную страницу:

- `views.py` — функция `page()` (единый HTML-каркас),
  view-функция `index()` и обработчик `page_not_found()`;
- `urls.py` — маршрут главной страницы.

Функция `page()` размещена здесь, потому что главная страница задаёт
общий вид всех остальных страниц. Остальные приложения импортируют её.

### `projects`

Django-приложение, отвечающее за проекты:

- `views.py` — view-функции `projects()` и `project_detail()`;
- `urls.py` — маршруты приложения;
- `models.py` — Django-модели (заполняется в следующих работах).

### `users`

Django-приложение, отвечающее за пользователей:

- `views.py` — view-функции `users()` и `user_detail()`;
- `urls.py` — маршруты приложения;
- `models.py` — Django-модели (заполняется в следующих работах).

### `applications`

Django-приложение, отвечающее за заявки:

- `views.py` — view-функции `applications()`, `application_detail()`,
  `statistics()`;
- `urls.py` — маршруты приложения;
- `models.py` — Django-модели (заполняется в следующих работах).

### `domain_projects.py`, `domain_users.py`, `domain_applications.py`, `domain_statuses.py`

Доменные модули, содержащие функции работы с сущностями предметной
области (загрузка, поиск, добавление, редактирование, удаление,
расчёт статистики). Используются совместно консольной и веб-версиями
приложения.

### `storage.py`

Отвечает за загрузку и сохранение данных. Выполняет преобразование:

- JSON → структуры Python;
- структуры Python → JSON.

Каталог `data/` создаётся автоматически при первом обращении.

### `utils.py`

Содержит вспомогательные функции:

- `parse_date()` — безопасный разбор даты;
- `parse_int()`, `parse_positive_int()` — разбор целых чисел;
- `parse_skills()` — разбор строки навыков;
- `next_id()` — вычисление следующего идентификатора в коллекции.

### `tests/`

Содержит автоматизированные тесты проекта для `pytest`.

## Запуск приложения

### Веб-версия (Django)

Перед первым запуском применить встроенные миграции Django:

```bash
python manage.py migrate
```

Выполнить системную проверку проекта:

```bash
python manage.py check
```

Запустить development-сервер:

```bash
python manage.py runserver
```

Открыть в браузере:

```
http://127.0.0.1:8000/
```

### Консольная версия (сохранена с ПР3)

```bash
python main.py
```
